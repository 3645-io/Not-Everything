# Clean-room policy

This file records where the project's design and code come from, and the rules that keep
them clean.

## Purpose

This project is inspired by voidtools Everything, which is closed-source freeware. We want
to be able to show, at any time, that our code was written independently: from public
documentation and permissively licensed code, and never from Everything's binaries, its
private formats or protocols, or from GPL or unclear-license projects.

A clean-room process protects against copyright claims. It does not protect against patent
claims, which have not been researched. This file is not legal advice; counsel should review
the project before launch.

## Allowed sources

You may read and learn from:

- voidtools' public support pages, FAQ and forum, as descriptions of behaviour. Write any
  text about that behaviour in your own words.
- Apple, Microsoft and Linux documentation (developer guides, API references, technotes,
  man pages).
- Code under the MIT or Apache-2.0 license, such as Cardinal, Lokii, Oil Find, Kestrel,
  `usn-journal-rs` and `ntfs`. Credit any code you adapt from them, and keep Apache-2.0
  code under its own license as described in the README's Licensing section.
- Public format descriptions published by voidtools for interchange, such as the EFU file
  list format, which may be implemented from that description.
- `docs/PLAN.md`, which was written from non-GPL sources only.

## Forbidden sources and actions

Never:

- decompile, disassemble or otherwise inspect the internals of any Everything binary;
- reverse-engineer `Everything.db`, its service protocol, or any other private format;
- copy voidtools help or documentation text, word for word or lightly reworded;
- read or copy GPL code, including FSearch, Cling, Orange and ANGRYsearch, or the GPL
  client `everything-sdk-rs` (which must also stay out of our dependencies);
- read any repository that has no clear license;
- add a GPL crate as a dependency.

## The four project rules

1. **Non-GPL design only.** Every design spec the project builds from is based on non-GPL
   sources alone.
2. **Separation of people from modules.** Anyone who has read FSearch's source code does
   not write the index-layout, query-matcher, file-format or sorting modules.
3. **Provenance log.** This file records the sources each run and each change consulted.
4. **No unclear licenses.** Nobody reads a repository whose license is missing or unclear.

## Restricted modules

The modules covered by rule 2 are the index layout (`fx-model`, `fx-index`; run 1.1), the
query matchers (`fx-query`; run 1.4), sorting (`fx-sort`; run 1.5) and the store's file
format (`fx-store`; run 1.6). Those runs, and every later change to these modules, work from
`docs/PLAN.md` and the modules' own code only, and never open anything under
`.claude/research/`: the owner's local research notes, which are gitignored and not in the
repository. `.claude/settings.json` blocks the one note that summarises a GPL project's
internals.

## Disclosure: GPL exposure during research

During the research phase, before any code was written, the researchers read:

- FSearch's GPL-2.0 C source at commit `1208a34`: its entry layout, database file format,
  sorting, query matchers and a dynamic-array helper;
- the READMEs of Cling, ANGRYsearch and Orange (GPL-licensed).

None of that is in the repository, as code or as design: `docs/PLAN.md`'s design cites only
non-GPL sources, and the restricted modules were written from the plan alone. The notes that
describe FSearch's internals stay in the owner's local, gitignored research folder.
