# Progress

## How to use this file

- Read this file first in every session, then only the `docs/PLAN.md` sections the run
  needs.
- One run per session. When a run ends, update its row in the runs table (status, branch or
  PR, measured numbers) and add any follow-ups below. Update this file last.
- If a run is cut short, set its status to **Paused**, commit the work in progress on its
  branch, and write under "Current state" exactly where the next session should resume.
- Benchmarks: record the machine and whether the cache was cold or warm next to every
  number.
- Statuses: **Not started**, **In progress**, **Paused**, **Done**.
- The run IDs and scopes mirror the "Runs: one session each" table in `docs/PLAN.md`. If
  the plan changes, re-export it and update this table to match.

- **Run 2.1, FSEvents edge cases (2026-11-10, branch `feature/2.1-fsevents-edge-cases`, draft PR #15 into `dev`; done unattended overnight with the owner's leave to skip plan approval, so the PR lists the defaults chosen):** every FSEvents flag Apple documents in `FSEvents.h` now ends in a change that loses nothing, and each route is tested end to end. Six lost-change cases were found and fixed in `fx-fs-macos` (`src/fsevents/{flags,change,cursor,stream,source}.rs`), each with a test written first and seen failing:
  - UserDropped and KernelDropped rescan everything the stream watches (`RescanVolume`), as `FSEvents.h` asks, instead of only the event's path.
  - The stream's path filter passes the events above it that rescan it (MustScanSubDirs coalesced onto a parent folder, dropped events on the volume root, a Mount or Unmount over it, the filtered root created, removed or renamed) and the volume-level flags on any path (`flags::admit`); `classify` maps them to a rescan of the scope root (`VolumeStream::scope_root()`, the filter or the mount point) and ignores metadata changes above it. A root folder that moves away now empties the index, and moving it back restores it.
  - Special events (a rescan request, Mount, Unmount, RootChanged, whose ID `FSEvents.h` gives as zero) are delivered even at or before the replay start (`CursorTracker::on_raw_event`).
  - EventIdsWrapped clears the replay start, ends the replay and moves the cursor to the wrap event's ID (`CursorTracker::on_ids_wrapped`); before, a resumed stream dropped every later event and the cursor stayed at the pre-wrap maximum.
  - A flag word with no item bit (`kFSEventStreamEventFlagNone`, "some change in the directory") rescans that folder instead of only checking it. A 45 s probe of a live root-volume stream saw 0 such words in 184 events.
  - Tests: a table of every documented flag through `map_event`, classify and admit cases, cursor cases (cross-platform); a live test that renaming a folder above the filter is delivered as a rescan of it; in `fx-engine`'s `tests/macos_e2e.rs`, a stored cursor ahead of the volume and one from another FSEvents database (written to the store by a source that reports a tampered cursor) each give `GapDetected`, a full rescan and an index equal to a fresh scan; 14 per-flag tests mute the real stream while files change, check that the index missed the changes, inject the one raw event FSEvents would send (routed as `FsEventsSource` routes it) and require an index equal to a fresh scan with the right rescan (subtree only, the root in full, or path checks only); a folder above the root renamed away and back. FSEvents cannot be made to send these flags on demand, hence the injection.

They stack and apply to terms, phrases and groups, and the innermost one wins. A bare `file:` or `folder:` is a plain kind filter. Other bare modifiers give a diagnostic and match everything. An unknown `word:` prefix stays literal text, so run 1.3 can add functions.
